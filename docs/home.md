# Home page

In Payload, open **Pages → Home** (`/admin/globals/home`). Choose German or English with the locale selector.

- **Hero** controls the introductory line, both heading lines, description and **Buttons**. All are optional: clear a field to hide it. Empty text adds no empty heading or line break. To show only the diagram, clear the four texts and remove the buttons.
- **Buttons** holds up to two call-to-action buttons under the heading. The first is the filled main button, the second an outlined one. Choose the destination with the page picker (see [Navbar editor](navbar.md#page-picker)) or an external URL; the language prefix is added automatically. Order is shared; labels are translated with the locale selector and fall back to German. Buttons with an unsafe or empty link are not shown.
- **Accounting companies** controls the top row. Choose one to six companies and drag rows to reorder them. Built-in wordmarks are local SVG assets. For another company, choose the custom option, enter its name and select an image from Media. Company selection/order is shared between locales; custom names are localized.
- **Diagram & workflow** controls the source label, text under Taxful, the customer card, the incoming lane (partner card and inbox card) and four workflow steps. The four incoming-lane labels are optional; empty fields show the default wording.

Home also supports reusable content sections and SEO settings. See [Public website builder](website-builder.md) for layout blocks, media, forms and the CMS inbox.

Use **Live Preview** to see unsaved edits beside the form, or **Preview** to open the preview page. **Save Draft** preserves edits without changing the public page; **Publish** makes them public. History keeps at most 25 versions. German is the fallback for missing English diagram/workflow labels and custom company names. Optional hero text stays hidden when empty in the selected language. Keep text short for the mobile diagram.

The home preview uses `/de?preview=true&previewGlobal=home` (or `/en`). It requires an authenticated CMS user. Only the selected global receives live updates: Home preview shows the published Navbar, and Navbar preview shows the published Home. Public reads use published content; anonymous draft and version-history access is denied. Preview population follows Media read access.

The file-import disclaimer, the “XML / PDF” chip, the “Prüfbericht” chip and the screen-reader hint for buttons that open a new tab remain application translations (`Home` in `messages/`). The companies illustrate file sources; they do not imply direct integrations. The diagram shows two lanes: invoices from accounting software go through Taxful to customers, and invoices received from business partners go through Taxful to the company’s invoice inbox (checked, with a validation report, original kept). The inbox is Taxful’s own Incoming files; do not describe received invoices as delivered to other apps. The former planned tax-office (ELSTER) branch is removed until direct submission exists.

## Modules and motion

`src/globals/Home.ts` composes fields from `src/fields/home/`. `src/lib/home/` separates CMS loading, fallback copy, provider metadata and display normalization (`homeContent` also filters the buttons). Small components and colocated CSS modules live in `src/components/home/hero/`; only the pause control and live preview need client state. No animation package is required.

Routes (`flow-paths.ts`): every company drops onto one shared rail that feeds a single trunk into Taxful. On phones, companies are arranged in columns of three and top-row routes run behind the tiles below them. Below Taxful, the customer and inbox routes mirror each other; the partner route rises straight up the middle. Desktop shows the customer, partner and inbox cards in one row; phones show customer and inbox side by side with the partner card centred below, its route passing between them. Below 420 px the two chips show icons only. Routes are generated for one to six companies; the viewBoxes (`0 0 880 440`, `0 0 360 440`) and the positions in the CSS modules must stay in step. Between 640 and 899 px the desktop scene is taller so the cards and format chip keep their spacing; strokes use `vector-effect: non-scaling-stroke`, so lines stay even and invoice dots stay round when the scene stretches.

Each company has a staggered phase in a shared 12-second CSS cycle (`flow-timing.ts`). An invoice — a dot with a soft tail — travels to Taxful (arrives at ~24%), triggers the hub glow (24–36%), then travels to customers (30–55%). The XML/PDF chip lights up as it passes (~41%) and the customer card as it arrives (~52%). The incoming lane carries two received invoices per cycle (`incomingTiming`): partner to Taxful (arrives at ~12%, hub glow 12–24%), then on to the inbox (17–40%), lighting the Prüfbericht chip (~27%) and the inbox card (~37%). Its phase is chosen per company count so its hub glows land as far as possible from the outgoing ones. Rings use `FlowRings` with the timing of their lane.

On load, the eyebrow, buttons and steps fade up, company tiles rise in sequence, routes draw in, Taxful settles and the destinations follow; the heading itself is not animated so it paints immediately. Pause stops the loop (comets, hub glow and rings); the loop also rests while the diagram is off-screen. Reduced-motion preferences show the complete diagram with no entrance, loop or hover motion.

## Database and verification

Apply Payload migrations `20261009_113849_home_page`, `20261109_115933_home_hero_actions` and `20261109_141329_home_incoming_lane` before deploying the app. The last one drops the two tax-office label columns (they only held the default wording) and adds the four optional incoming-lane labels; its down migration restores the tax-office columns with their default wording. The second adds only the button tables and, in plain SQL (independent of later schema changes), publishes the starter buttons (“Kostenlos starten” → `/signup`, “Preise ansehen” → `/pricing`, with English labels) when Home has no buttons yet and no pending draft; otherwise add them in **Pages → Home**. The first migration adds only Home/versions tables and initializes the current published German/English copy and six providers. None changes existing Navbar, staff or customer records. All have been applied to the local development database.

Live Preview requests run in order (`src/lib/live-preview.ts`), so a slower, older response can no longer overwrite newer edits when several fields change at once. All preview components (Home and pages, service pages, navbar, footer) use `useOrderedLivePreview`.

Generate schema artifacts with `pnpm generate:types` and `pnpm generate:importmap`. Check CMS permissions, localized publication and drafts with `tests/int/home.int.spec.ts`, unsaved preview with `tests/int/home-preview.int.spec.ts`, and the actual editor with `tests/e2e/home.e2e.spec.ts`. `tests/e2e/frontend.e2e.spec.ts` covers bilingual rendering, hero buttons, themes, mobile layout, preview authentication, motion controls, staggered timing and reduced motion. `tests/int/home-flow.int.spec.ts` checks the generated routes for one to six companies and the button filtering.
